# Execution Record Storage v3

继承 [v2](execution-record-storage-v2.md) 的独立输入／结果、统一活动小字段、按页读取和按需详情，
以及 [v1](execution-record-storage-v1.md) 的输出裁剪、删除登记与安全回收。本版只减少新操作的重复正文及无展示变化的写入。
command.result、审批、输入投递、运行结算、未知结果不自动重放和 Run 目录模式均不变。

## 创建与旧数据

migration 203 / schema 153 是最低读写实现；复用既有数据库准入拒绝不认识新格式的旧 Core。
新操作首次写入格式 4，后续固定按该格式收尾。旧格式 1、2、3 继续各自生命周期、正文布局和 classifier；
没有可靠操作 ID 时仍保持独立观察，不根据相同命令文本归并。

迁移只加可空的 result_digest 小字段，扩大格式触发器和兼容视图的格式集合。不扫描、回填或改写旧操作、
Blob、消息、目录快照，不在读取时迁移，不提供降级迁移。现有数据库和 Blob 不因升级自动缩小。

## 成功规范化后的修改正文

格式 4 的成功 Codex 文件操作，只有在 runtimeDiff 已准入可用、原生条目的路径（复用已有工作目录路径归一）、
修改种类及正文与规范化条目完全对应时，才去掉原生 item.changes 中的 diff 字段。update 对照 diff，
add 对照 after，delete 对照 before；路径、kind、移动信息和未知原生元数据保留。

完整权威正文仍在同一结果的 runtimeDiff 中，详情和文件修改展示复用既有解析。失败、未准入、不匹配或独有正文
原样保留。格式 1–3 的原始与规范化内容均不修改。运行结束的 Files Changed 聚合保持原算法和独立详情 Blob，
本版不把有计算语义的汇总替换成每次打开重算整轮。

## 预览预算与必要事实

格式 4 每份 input_preview_json / result_preview_json 最多 **16,384 个序列化 UTF-8 字节**；分别计预算，
一个操作两份预览合计至多 32 KiB。它不是完整操作或完整修改内容的大小上限，也不是普通输出预算。
完整内容在现有 inline 门槛内保持原样；超过门槛时完整正文按原机制保存一次 Blob，数据库只保留有总预算的预览。
继续保留过大／丢失正文的明确状态与摘要，不把预览宣称为完整内容。

预算计算包含 JSON 键、转义、标记与结构开销，保持字符完整，同时沿用每层集合项数和字符串展示限制。
先为身份、状态、关联摘要、生命周期和后台任务的小字段留空间，再填充大参数／修改内容；路径和命令等精确值
不能变成可被误用的前缀。全量数据仅在所选操作详情中按需读取，列表不读取整轮 Blob。

格式 4 的已准入 runtimeFileOperation 小对象随 activity_meta_json 保存，不复制输入、输出或修改正文。
单文件预览依旧按选中 Evidence 主键核对会话、Run、epoch、工作目录和路径，使用这份必要事实，
不依赖可能被省略的预览字段、不进入整轮活动联合查询。格式 1–3 的原直接读取路径保持。

## 结果摘要与进度写入

普通输出仍先按 7,680 UTF-8 字节裁剪，再持久化；被裁掉的后缀不进入 Rovai 的数据库、Blob、持久事件或生产日志。
智能体收到的完整工具结果不变。输入、用户回复和修改正文不套用这一输出预算。

格式 4 将既有 resultDigest 结果证明保存于同一操作的 result_digest 标量；原有详情、分页、SQL、分组和关联读取
在需要时还原该字段。摘要仍针对原协议提供的完整输出值计算，不改变快照／追加模式原有含义，不把片段摘要
升级成累计结果证明。旧格式继续读原 JSON 字段。

同一进行中操作若保存后的输入／结果、阶段、事件类型、种类和截断状态均不变，只是完整输出摘要变化，
仅更新标量；不重新写入正文、Blob、活动小字段，不推进可见 revision/change_sequence。
这不等于 SQLite 零写入，也不丢弃摘要：重启后仅收到结束状态仍拥有最新结果证明。

完整替换、有序追加、后续状态、终态冲突和取消围栏仍使用既有归约。预算耗尽继续消费 Runtime 协议；
合法短结果替换仍更新正文。晚到开始、冲突终态按原规则保持已接受的结果摘要；终态证明变化仍推进 revision，
让结果关联重新计算。没有通用节流器或新的结果回放机制。
