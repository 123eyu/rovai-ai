# Runtime Launch and Verification v64

继承 [v63](runtime-launch-and-verification-v63.md) 的启动、恢复、输入保护和进程边界。
本版替换继承自 [v41](runtime-launch-and-verification-v41.md#返回值与诚实展示) 的正式页面版本取值规则；
草稿检查、失败反馈、检查结果的代次围栏与执行准入保持。

## 已知版本的保存与展示

`reportedVersion` 仍为可空字符串，沿用现有快照字段，不新增版本缓存、数据库迁移或轮询。
版本是程序信息，不证明认证、能力、模型目录或本次完整检查成功。

- 正式发现已找到程序时，优先展示该程序本次实际读到的非空版本。
- 本次未读取版本、读取失败或返回空值时，可以复用同一 Installation 的已知版本，但当前发现路径必须
  与 Installation 路径一致，且当前非空 executable fingerprint 必须与保存版本的快照一致。
- 搜索环境代次只在有效搜索输入或配置实际变化时推进，不单独决定版本展示。检查其他 Runtime 不得让版本消失或
  重新显示已经属于另一份程序的历史版本。
- 未找到程序、路径不一致、fingerprint 缺失或变化时，不回退旧版本。尚未完成入口发现时保持未知。
- 快照更新没有带来新版本时，仅在同一 Installation、非空且相同的 executable fingerprint 下保留
  原版本；真正替换程序后不得把旧版本写成新程序的版本。新的非空版本正常替换旧值。
- 已有静态发现、启动或主动检查读到非空版本后，按当前 Installation／路径／程序指纹保存到同一快照字段。
  首次没有健康快照时仅建立 `installed_unverified`；升级后的旧快照按既有静态规则重置，不能将旧认证或能力
  归给新程序。普通启动的版本缓存保存失败不阻断执行。
- 健康快照过期或检查失败与程序版本分开判断；身份仍匹配时可显示已知版本，失败原因和本次检查结果
  继续如实返回，不把保留版本包装为本次检查成功。

设置目录和队员配置统一消费 Core 的 `runtimeAvailability.reportedVersion`。Renderer 不再自行从
Installation 快照补齐版本，避免两个页面对同一程序显示不同结果，或重新显示 Core 已排除的旧版本。
高级诊断可以保留原始历史快照。

## 检查与执行边界

启动和 rescan 继续只做既有静态入口发现，不为显示版本运行批量 `--version` 或完整健康检查。
页面打开和普通执行不增加健康探测；已有实际启动需要的有界版本读取保持原语义。
版本未知或读取失败不单独阻止配置、创建 Run 或普通执行，必要的协议、权限和显式模型验证仍由真实 Host 完成。
用户主动检查继续沿用有界 Check Manager、身份复核、失败说明和进程清理。

## 静态发现与诊断等待范围

普通发现只解析入口、确认执行条件和安装身份。路径与已保存的 `ExecutableFileIdentity` 未变时复用
已有指纹；首次发现或升级在同一工作任务内读取前身份、计算指纹、读取后身份，直接形成
`VerifiedDiscoveredRuntimeEntry`。普通原生安装未变时完整哈希 0 次，首次或升级 1 次；Windows shim、
应用 bundle 保留现有依赖身份规则。静态发现不启动智能体子进程，不为版本展示额外读取整份程序。

每项工作独立提交和发布；提交复用搜索代次与 Installation ID／version 条件保护，不再次完整哈希。
同代次已更新的安装记录不能被迟到结果覆盖。刷新保留已有列表与诊断说明，后台工作失败不等于未安装。

数据库、启动配置及搜索代次入库完成后即可开始发现，与可选子系统初始化并行；恢复任务继续等待既有
子系统就绪门禁。单项诊断优先复用当前入口和搜索环境，只有入口失效或用户重新检测才捕获环境；
输入未变不推进 generation，相同目标仍由现有 Check Manager 合并。

`runtime.status.get` 只返回既有 `runtime_health_payload()` 聚合数据，不执行 Git 或 Runtime 探针。
页面与诊断回调共用一次 Runtime 状态及安装列表读取；请求期间有新事件时标记补刷，补刷期间同样处理。
不等待 Overview、导航或记忆读取。界面 pending／错误仅限制对应智能体，顶部刷新只限制同轮重复刷新。
完整检查保留为用户主动的“诊断”，返回值仍代表真实诊断结果；发现程序只显示“已安装”，不等同 Ready。
诊断失败、版本未知或目录过期不额外成为保存配置、默认模型启动或复用已有 Host 的门槛。
